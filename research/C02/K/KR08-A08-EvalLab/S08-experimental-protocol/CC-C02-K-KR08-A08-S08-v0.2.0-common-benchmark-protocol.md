# Common experimental challenge — E01–E08
All variants share source bytes, campaign, transcript version, clock, renderer (except explicit rendering test), seed, permissions, gold hash and assigned roster. Gold scorer runs separately; no labels, queries, alternative groups or target boundaries in model inputs. Oracle arms isolated from primary results. Dev caps initially proposed: at most 30/60/120 provider calls per 90-min source (phase reserve explicitly configured), K=10/20/40 proposals per source-hour, proposal union ≤ 10/20/30% source time; retrieval 2/4/8 calls per candidate, max 60/120/240 seconds evidence read; token/frame limits must be measured and frozen on dev before holdout. These are engineering starting points, not thresholds or measured capacity; use one frozen budget vector per comparison, vary one factor at a time for cost curves. No paid inference without approval. For E07 modality access intentionally varies, all other caps equal; frames and image resolution reported. For E01 use actual pinned fixed window/stride from source config, not an assumed number. All experiment runs have expected row for every source/variant/seed, including failures.

Primary metrics: E01 complete-thought + recall@K; E02–03 essential closure; E04 paired preferences and approved yield; E05 typed relation F1 and verified closure; E06 faithful admissible interval rate; E07 distinct recall@K; E08 approved unique event yield/assigned VOD. All remain subject to shared hard gates. Run same seed and roster across arms, record cold/warm separately, 3 seeds if stochastic dev resources permit (report actual n); no rerun cherry-picking. Compare matched pairs on same source, macro creator and micro event metrics, raw counts, paired uncertainty. Treat failures as zero yield, not discarded. Publish representative/challenge tables separately, novelty slices multi-label and denominators. 
Acceptance plan: stage 0 schema/hash/coverage/denominator/duplicate/failure fixtures pass; stage 1 run small dev pilot and establish disagreement, paired variance, baseline runtime and operational budget; stage 2 pre-register effect margins and max acceptable cost/failure/faithfulness degradation with Nexus before any holdout run; stage 3 evaluate locked holdout once, record CI and raw per-creator results; stage 4 shadow review, manual approval only. Serious faithfulness errors in reviewed holdout block promotion until understood and repaired (zero observed is not proof of zero risk). No practical effect size estimated from synthetic checks; e.g. one additional approved distinct event per 4 VODs (0.25/VOD) is a discussion starter only, not an approved threshold. If intervals overlap margin or sample too small, collect more creators or retain baseline. No gate can be passed by oracle-only results or rendering tests.
